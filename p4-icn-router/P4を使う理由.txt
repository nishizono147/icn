この研究で P4 を使う理由
（2026-10-12 作成）

================================================================
■ 一言でいうと
================================================================

ネットワークの中継点にあるスイッチを、速さを保ったまま ICN ルータ（IWP）にできるから。
そのためにはスイッチのチップの制限の中で作る必要があり、
どう作るかがこの研究の中身になる。

================================================================
■ 前提：スイッチの中身は 2 つに分かれている
================================================================

           スイッチ
  +----------------------------------+
  |  管理用の CPU                     |  設定の受け付け、経路の計算、P4Runtime の窓口など
  |   （小さなコンピュータ）           |  パケットはごく一部しか届かない
  |                                  |
  |  専用のチップ（ASIC）              |  すべてのパケットはここを通って出ていく
  +----------------------------------+
     ポート ===================== ポート

・専用のチップ: 届いたパケットを処理して別のポートから出す。大量のパケットを回線の速さで処理できる
・管理用の CPU: 設定や経路の計算をする係。パケットは CPU に寄らずにチップだけを通って出ていく

================================================================
■ P4 と VPP の違い
================================================================

・P4 : スイッチの専用のチップの動きを書き換えられる言語
       → スイッチ自体が IWP になる
・VPP: サーバ（コンピュータ）の CPU で動くソフトウェア。hICN のプラグインがある
       → スイッチの管理用の CPU では動くが、パケットはそこを通らないので ICN の処理はできない
       → VPP で IWP を作るなら、ポートをたくさんつけたサーバを中継点に置き、
         そのサーバをルータとして使う（ソフトウェアルータ）

  VPP:  --- スイッチ --- [サーバ（VPP）] --- スイッチ ---
                          ここで ICN の処理。量が増えたらサーバ（CPU）を増やす

  P4:   --- [スイッチ（P4）] --- [スイッチ（P4）] ---
              スイッチのチップ自身が ICN の処理をする

荷物の仕分けにたとえると
・VPP: 作業員が手で仕分ける。どんなルールにも対応できるが、量が増えたら人を増やすしかない
・P4 : 仕分け機械の動きを書き換える。大量の荷物を速く仕分けられるが、機械にできる動きは限られる

  |                    | VPP                        | P4                                   |
  |--------------------|----------------------------|--------------------------------------|
  | 動く場所           | サーバの CPU               | スイッチの ASIC、SmartNIC/DPU、FPGA、 |
  |                    |                            | ソフトウェア（BMv2、P4-DPDK など）    |
  | 書ける処理         | C で何でも書ける           | 制限が多い（後述）                   |
  | 速さ               | CPU のコア数に比例         | ASIC なら 1 台で大量に、決まった遅延で |
  | 可変長の名前       | 扱える                     | 扱いにくい                           |
  | 大きなキャッシュ   | GB 単位で持てる            | ASIC のメモリは数十 MB 程度          |

注意: 「データプレーンを柔軟にプログラムできるから」は、VPP と比べると P4 を使う理由にならない。
      VPP の方が柔軟だから。P4 の強みは「柔軟に書ける」ではなく「ハードウェアの中に書ける」こと。

================================================================
■ 理由 1：スイッチのチップに ICN の処理を入れられる（P4 を使う目的）
================================================================

・スイッチはネットワークのすべての中継点にすでにある
・パケットはすべてスイッチの専用のチップを通る
・そのチップの動きを書き換えられるのは、事実上 P4 だけ

ICN は、すべての中継点で、Interest が来るたびに
「キャッシュにあるか」「PIT に記録するか」「どこに送るか」を判断する。
これを大量に速くこなすには、サーバの CPU よりスイッチのチップの方が向いている。
P4 なら、新しくサーバを置かずに、中継点のスイッチ自体を速いまま IWP にできる。

言い換え（論文向け）:
  ハードウェアのデータプレーンをプログラムできるため、回線の速さで動くネットワーク機器の中に、
  パケットごとに自律的に判断するキャッシュ機能を組み込める。

================================================================
■ 理由 2：チップの制限の中で作る工夫が研究になる（研究の問い）
================================================================

スイッチのチップは速い代わりに、できることに制限がある。
・長さの決まっていない情報（可変長の名前）を読めない
・同じ処理を繰り返せない（recirculate は実機では帯域が限られる）
・覚えておける量（メモリ）が少ない
・表（マッチアクション表）は外のプログラムしか書き換えられない
  （パケットの処理中に書けるのは register だけ）

VPP なら制限がないので、MCD も off-path 共有も素直に書けば動く。それは開発であって研究にはならない。
P4 では制限の中で動くように工夫する必要があり、その工夫が研究の中身になる。

これまでの設計は、すべてこの制限への対処として説明できる:

  | 制限                                 | この研究での工夫                                         |
  |--------------------------------------|----------------------------------------------------------|
  | 可変長の名前を読めない               | 名前を階層ごとのハッシュにして固定長にした               |
  | 表はパケットの処理中に書き換えられない | パケットごとに書く PIT とキャッシュは、名前のハッシュを   |
  |                                      | インデックスにした register に置いた                      |
  | 繰り返し（recirculate）は実機で限られる | チャンクごとに Interest を送る chunk_pull を選んだ       |
  | メモリが少ない                       | 決まった大きさの register、衝突したら上書き（置き換え）   |

研究の問い:
  動的で自律的なキャッシュ配置（MCD、off-path 共有）を持つ ICN ルータを、
  プログラム可能なネットワーク機器のデータプレーンの制約
  （固定長の処理、限られたメモリ、繰り返しのない処理）の中で実現できるか。
  実現するために、名前、PIT、キャッシュ、キャッシュの位置の通知をどう設計すればよいか。

理由 1 と理由 2 の関係:
・理由 1 は P4 を使う「目的」（中継点のスイッチを速いまま IWP にしたい）
・理由 2 はそこから生まれる「研究の問い」（そのためには P4 の制限の中で作る必要があり、どう作るかが研究）
・理由 1 だけだと「P4 で作った」という報告で終わり、理由 2 だけだと「なぜわざわざ制限の多い P4 で？」と聞かれる。
  2 つをセットで説明する。

================================================================
■ 理由 3（補足）：同じプログラムを色々な機器で動かせる
================================================================

P4 は、スイッチの ASIC、SmartNIC / DPU、FPGA、ソフトウェアに、同じ言語で載せられる。
事業者が持っている機器に合わせて IWP を置けるので、導入のしやすさにつながる。VPP は CPU 専用。

================================================================
■ 「なぜ VPP（hICN プラグインの拡張）ではなく P4 なのか」と聞かれたら
================================================================

  VPP はサーバの CPU で動くので、IWP にするには中継点にサーバを置く必要がある。
  本研究は、中継点にすでにあるスイッチのチップ自体を IWP にすることを目指している。
  それができるのは P4 だけで、その代わりチップの制限の中で動的なキャッシュ配置を実現する必要があり、
  その設計が本研究の貢献である。

================================================================
■ NFD・hICN との違い（P4 に関係する部分）
================================================================

  |              | どこで処理するか      | キャッシュの置き方   | IP との共存                              |
  |--------------|-----------------------|----------------------|------------------------------------------|
  | NFD（NDN）   | サーバ                | 通ったら全部に置く   | NFD どうしを設定した UDP トンネルでつなぐ |
  | hICN         | サーバ（VPP）         | 通ったら置く         | 名前を IPv6 アドレスにする（IPv6 のみ）   |
  | この研究     | P4 スイッチのチップ   | MCD + off-path 共有  | IWP を自分で見つけるオーバーレイ（予定）  |

・NFD も「ソフトウェアの ICN ルータ」なので、「ソフトウェアだから導入しやすい」は差別化にならない
・NFD も hICN も、キャッシュの置き方は「通ったら置く」で、配置の工夫はしない

================================================================
■ 気をつけること
================================================================

1. BMv2 では速さを示せない
   BMv2 は P4 を試すためのソフトウェアのスイッチで、遅い。「チップの速さ」は実測できない。
   示せるのは次のようなこと:
   ・実機の制約を守った設計になっていること（表や register の数、処理の段数、recirculate を使わない）
   ・1 パケットあたりの処理の量（register を何回読み書きするか）
   ・可能なら P4-DPDK や実機向けのコンパイラでコンパイルが通ること
   ・速さに左右されない指標（ヒット率、ホップ数、Producer に届いた要求の数）で評価する

2. コンテンツ本体の置き場所
   スイッチのチップのメモリは小さいので、コンテンツ本体をスイッチの register に置く今の形は、実機では成り立たない。
   「スイッチは名前・PIT・FIB・キャッシュの判断を回線の速さで行い、本体はつないだ記憶装置に置く」
   といった分担を考える必要がある。
   その場合「本体を置くサーバがあるなら、そこで VPP を動かせばいいのでは？」と聞かれるので、
   「すべての中継点で、すべての Interest の判断をするのはスイッチ。サーバは本体を保存して返すだけで、
   キャッシュから返すときしか通らない」という役割分担で答える。
   修士論文では、BMv2 の上での簡略化として本体を register に置いたまま進め、制約として明記する。

3. P4 のスイッチの ASIC の状況
   P4 の代表的なスイッチの ASIC だった Intel の Tofino は、2023 年に Intel が次の世代の開発をやめると発表している
   （要確認）。「スイッチの ASIC」だけに頼らず、DPU（AMD Pensando など P4 で書けるもの）や FPGA も含めた
   「プログラム可能なネットワーク機器」として主張する方が安全。
