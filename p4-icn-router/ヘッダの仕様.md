# ヘッダの仕様

（2026-10-22 作成）

chunk_table を土台にした今後の実装（FIB、水平キャッシュ）で使うパケットの形。
後輩の実装（水平キャッシュなど）も、この形に合わせる。chunk_pull は比較用なので、今の形のまま変えない。

## パケットの種類

| EtherType | パケット | 向き |
|---|---|---|
| `0x88B5` | Interest | Consumer → Producer の方向 |
| `0x88B6` | Data | Producer（またはキャッシュを持つスイッチ）→ Consumer の方向 |
| `0x88B7` | 通知（新しい） | スイッチ → 隣のスイッチ（1 ホップ先まで） |

どれも Ethernet のヘッダ（14 バイト）の上に、直接 ICN のヘッダを載せる。IP のヘッダはない。
数は大きい桁から並べる（ネットワークバイトオーダー）。

## Interest（20 バイト）

```
 0               6               12   14         18  19  20
 ├── 宛先 MAC ───┼── 送信元 MAC ──┼type┼── name ──┼flg┼rdr┤
 │    6 B        │     6 B        │0x88B5  4 B    │1 B│1 B│
 └───────────────┴────────────────┴────┴──────────┴───┴───┘
   Ethernet（14 B）                     ICN ヘッダ（6 B）
```

| 欄 | 大きさ | 中身 |
|---|---|---|
| `name` | 32 bit | コンテンツの名前。名前を入れるまでは content_id（1〜10 = `contents/content1〜10.bin`） |
| `flag` | 8 bit | 1 = Consumer から直接来た。スイッチは転送するときに 0 にする。エッジ（Consumer の隣）かどうかの判断に使う |
| `redirect_by` | 8 bit | ECST でリダイレクトしたスイッチの番号（1〜）。0 = リダイレクトされていない |

Consumer が送るときは `flag = 1`、`redirect_by = 0`。

## Data（280 バイト）

```
 0       6       12   14         18   20   22  23  24                              280
 ├宛先MAC┼送信元MAC┼type┼── name ──┼total┼chunk┼flg┼src┼──────────── data ────────────┤
 │ 6 B   │  6 B   │0x88B6  4 B   │ 2 B │ 2 B │1 B│1 B│            256 B             │
 └───────┴────────┴────┴─────────┴─────┴─────┴───┴───┴──────────────────────────────┘
   Ethernet（14 B）    ICN ヘッダ（10 B）                      中身（256 B）
```

| 欄 | 大きさ | 中身 |
|---|---|---|
| `name` | 32 bit | コンテンツの名前（Interest と同じ） |
| `total_chunks` | 16 bit | 全チャンク数（今のスイッチの上限は 10） |
| `chunk_id` | 16 bit | このチャンクの番号（0 〜 `total_chunks - 1`） |
| `flag` | 8 bit | 1 = 受け取ったスイッチがキャッシュする（MCD）。キャッシュしたスイッチは 0 にして下流へ流す |
| `source_switch` | 8 bit | この Data を作った場所。0 = Producer、1〜 = スイッチの番号。計測で返した場所を確かめるのに使う |
| `data` | 256 B | 中身。最後のチャンクで余った分は 0 |

Producer とキャッシュから返すスイッチは `flag = 1` で送る。

## 通知（20 バイト）

```
 0       6       12   14         18   19   20
 ├宛先MAC┼送信元MAC┼type┼── name ──┼stat┼sndr┤
 │ 6 B   │  6 B   │0x88B7  4 B   │1 B │1 B │
 └───────┴────────┴────┴─────────┴────┴────┘
   Ethernet（14 B）    通知のヘッダ（6 B）
```

| 欄 | 大きさ | 中身 |
|---|---|---|
| `name` | 32 bit | どのコンテンツか |
| `state` | 8 bit | 1 = あり（キャッシュした）、0 = なし（消した） |
| `sender` | 8 bit | 知らせたスイッチの番号（確認用。受け取った側は、届いたポートを ECST に記録する） |

通知は、最後のチャンクの Data（あり）や、キャッシュから返し終えたときの Interest（なし）のコピーを、
egress で書き換えて作る。受け取ったスイッチは ECST を更新して捨てる（転送しない）。
詳しくは [水平キャッシュの設計.md](水平キャッシュの設計.md)。

## MAC アドレスの扱い

| パケット | 今の扱い |
|---|---|
| Interest | Consumer は s1 の MAC（`08:00:00:00:01:00`）宛てに送る。スイッチは、送信元 MAC を届いたときの宛先 MAC（自分）に、宛先 MAC を次の行き先の MAC に書き換える。次のスイッチは送信元 MAC で転送先を引く（`foward_interest`） |
| Data | スイッチが宛先・送信元とも `ff:ff:ff:ff:ff:ff` にする。PIT のポートへ送るので MAC は使わない |
| 通知 | `ff:ff:ff:ff:ff:ff`。届いたポートで扱うので MAC は使わない |

Interest の「送信元 MAC で転送先を引く」仕組みは、FIB に置き換えるときにやめる。そのときの MAC の扱いは FIB の設計で決める。

## 今の chunk_table からの変更

| | 今 | この仕様 |
|---|---|---|
| Interest | `content_id`(32) `type`(16) `flag`(8) `source_switch`(8)。22 バイト | `name`(32) `flag`(8) `redirect_by`(8)。20 バイト。`type` と `source_switch` は使っていなかったので消す |
| Data | `content_id`(32) `total_chunks`(16) `chunk_id`(16) `flag`(8) `source_switch`(8) `data`(256 B) | 同じ（`content_id` を `name` と呼ぶだけで、位置と大きさは変わらない） |
| 通知 | なし | 新しく足す |

## 名前を入れるとき

名前の欄は 32 bit のまま。ホストが名前（例: `image1`）を 32 bit のハッシュにして入れる。
スイッチは文字列を扱わない。ハッシュにすると register の位置がぶつかることがあるので、
キャッシュ・PIT・ECST に名札（ハッシュ全体）を持たせて照合する（詳しくは名前の設計のときに決める）。
